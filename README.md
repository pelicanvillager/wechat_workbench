# 微信公众号工作台

工作台在 Mac 上运行，把每日热点、选题、写作、配图、排版、微信草稿与发表记录放在同一个页面。原稿以 Markdown 保存，每篇文章有独立目录。

仓库提供工作台源代码、网页界面和 Mac 启动脚本。首次运行会建立空的数据目录。基础排版在本机完成，可单独使用。

## 启动与固定到程序坞

1. 克隆仓库后，在访达打开仓库目录，双击 `启动公众号工作台.command`。默认地址为 [本机工作台](http://127.0.0.1:8765/)，需要 Python 3.9 或更新版本。
2. 要固定启动入口，将这个 `.command` 文件拖到程序坞最靠近废纸篓的分隔线右侧。程序坞在屏幕侧边时，拖到分隔线下方。以后点该入口即可运行原文件。[Apple 程序坞说明](https://support.apple.com/zh-cn/guide/mac-help/mh35859/mac)
3. 使用期间保留启动窗口。工作台已运行时，直接打开本机地址即可。

也可以在仓库目录运行：

```sh
python3 workbench.py --open
```

默认监听 `127.0.0.1:8765`。端口已被占用时，可运行 `python3 workbench.py --port 8766 --open`。启动后按终端显示的地址访问。

## 从热点到成稿

1. **看热点。** 当天首次打开工作台时会抓取百度、微博、知乎和头条热榜。可按平台查看或手动刷新。优先查看每条热点的来源和抓取时间，旧快照仍显示原抓取时间。
2. **定选题。** 从热榜收藏一个题，或手动新建。填清读者问题、角度、来源和手头已有的真实材料，然后点「开稿」。
3. **写完整稿。** 可以手写，也可以在文章页顶部点击一键成稿。工作台调用本机已配置的 AI 写作工具，使用当前稿件、编辑资料、来源记录和近期标题。生成成功后会回填并保存标题、摘要、标签和正文，另存来源、编辑建议及直接粘贴版。已有正文会在确认后留存旧版。也可以用「复制创作任务」交给其他 AI 模型。
4. **配图并审核。** 添加封面与正文图，补写图注。查看标题、摘要与宽幅、聊天卡片裁切示意，可打开原图。展开「编辑检查」核对开头、标题兑现、分享理由和图源。将待作者确认的稿件标为「待审核」。
5. **预览并交付。** 「生成直接粘贴版」会在文章目录的 `output/` 生成 `公众号直接粘贴版.html`。可分别复制富文本正文、标题、作者、摘要和标签。查看含本地图的预览时，从文章目录打开 HTML，图片依赖相对路径。

## 微信草稿与发表

- **手动录入。** 将排版正文粘贴到微信公众号后台，按插图提示上传本地图并替换提示，再上传封面、手机预览和手动发表。
- **提交微信草稿。** 本地排版后直连微信接口。需要目标公众号的 AppSecret、草稿接口权限及本机实际出口 IP 白名单。在终端运行 `python3 workbench.py --configure-wechat`，按提示输入 AppID 和 AppSecret，再到「发表台」点击「检查微信连接」。密钥回车确认前无回显，保存至用户目录下的 `~/.config/wechat-workbench/wechat.json`。鉴权、读取草稿箱、实际创建草稿是三个不同的验证阶段。
- **核对提交结果。** 取得微信返回的草稿 ID 后，工作台显示「已创建草稿」。如果显示「待核对」，先到微信草稿箱按标题查找，核对后再决定是否重试。
- **登记正式发表。** 在微信后台完成发表后，回到工作台登记正式文章链接与实际发表时间。

## 接入 AI 写作工具

手动写作和「复制创作任务」开箱可用。使用一键成稿前，将 `WECHAT_WORKBENCH_AI_COMMAND` 指向你信任的本机可执行程序，再从设置该变量的终端会话启动工作台。

适配程序从标准输入读取一份 UTF-8 创作任务，在标准输出返回一个 JSON 对象。以下六个字段均为字符串：

| 字段 | 内容 |
| --- | --- |
| `title` | 文章标题，最多 32 字 |
| `summary` | 摘要，最多 120 字 |
| `tags` | 英文逗号分隔的标签 |
| `body` | 完整 Markdown 正文 |
| `sources` | 实际核对来源的 Markdown 记录，可为空 |
| `editorial` | 备选标题、审稿意见和配图建议 |

模型供应商和联网核对能力由适配程序决定。编辑日志可写到标准错误。工作台校验返回字段后才保存并导出，已有正文在重写前会留档。

## 文件与 AI 助手协作

数据默认写入仓库的 `data/`。可在启动前设置 `WECHAT_WORKBENCH_DATA_DIR`，指向自己的运营目录。已有文章可按下表的目录结构放在该位置。

| 文件或目录 | 用途 |
| --- | --- |
| `01_选题/选题池.md` | 已有选题表 |
| `02_文章/<年份>/<文章目录>/article.md` | 原稿，含标题、作者、摘要、标签和正文 |
| 同一文章目录下的 `notes.md`、`sources.md` | 写作角度、素材线索及事实核对记录 |
| 同一文章目录下的 `images/`、`output/` | 封面、正文图、编辑建议和排版文件 |
| 数据目录的 `工作台数据.json` | 新选题、热榜快照及稿件状态 |

AI 助手可以先读取文章目录与选题资料，再生成一篇围绕具体读者问题的完整稿件。把可核实的引用链接放入 `sources.md`，内部审稿意见另存。热点排名用于发现线索，事实以原始发布资料为准。亲历材料不足时，用明确标注的假设例子，或收窄为基于公开事实的文章。标签用英文逗号分隔，未指定署名时留空。

批量处理前先核对每篇文章的当前版本。使用已运行的工作台时，可以通过 `GET /api/state` 了解列表，按返回的稿件 ID 通过 `GET /api/article?id=…` 读取单篇文章。通过页面保存和导出，可同时维护文章状态与输出文件。向微信提交草稿或正式发表前，先由用户确认对应稿件、账号与操作。

连接失败时先看「发表台」的提示。微信返回 `40164` 时，核对微信识别的出口 IP 以及该公众号的白名单。凭证、草稿、选题、热榜缓存及发表记录保存在本机。
